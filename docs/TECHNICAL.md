# Wii Fit U 한글화 기술 문서

일본판 「Wii Fit U」(WUP-U-ASTJ, 본편 `0005000010102200` v32 / 업데이트 `0005000E10102200` v81)의
파일 형식과 한글화 방식, 작업 중 밟은 함정을 정리했습니다.

공개 문서를 찾지 못한 형식(jARC·jCMP·jIMG·JFNT, GTX 타일 배열)은 직접 뜯어 알아낸 것입니다.
모든 형식은 **고치지 않고 다시 꾸미면 원본과 바이트 단위로 같아지는지**를 기준으로 검증했습니다
(`tools/*_tool.py roundtrip`).

## 1. 전체 구조

엔진은 `gameConfig.ini`에 "jet"으로 적혀 있고, Wii용 Wii Fit Plus에서 옮겨 온 것입니다.
그래서 Wii 시절 자산(BRFNT 글꼴, U8 아카이브)과 Wii U 자산(GTX 텍스처)이 섞여 있습니다.

업데이트가 본편 파일을 덮어씁니다. 같은 경로에 둘 다 있으면 업데이트 쪽이 쓰입니다.
한글화 대상 13개 중 12개는 업데이트에 있고, `ui/aot_tex.jarc`만 본편에 있습니다.

| 확장자 | 내용 |
|---|---|
| `.carc` | Yaz0 압축된 U8 아카이브 |
| `.jarc` | 자체 아카이브. jCMP(zlib)로 포장된 것과 생짜인 것이 섞여 있다 |
| `.jtex` | jIMG 컨테이너 안에 Wii U GTX 텍스처 |
| `.jmdl` | 3D 모델. 안에 jIMG 텍스처가 들어 있다 |
| `.jfnt` | 글꼴. 유니코드 범위표 + 글자 폭표 + 글리프 아틀라스(jIMG) |

### jCMP (zlib 포장)

```
0x00  'jCMP'
0x04  u32  파일 전체 크기
0x08  4B   flags      (flags[0] = zlib 압축 수준)
0x0C  u32  압축된 크기
0x10  u32  풀린 크기
0x14  zlib 데이터
```

**다시 압축할 때 원본과 같은 flags를 써야 합니다.** 압축하지 않고 생짜로 넣으면 게임은 읽지만
파일이 18MB에서 90MB로 부풉니다.

### jARC (아카이브)

```
0x00  'jARC'
0x04  u32  전체 크기
0x08  u32  버전 (0x01200300)
0x0C  u32  항목 수
0x10  항목표 16바이트 x N:  u32 오프셋, u32 크기, u32 이름 오프셋(파일 기준 절대값), u32 CRC32(이름)
      이름 블록 (널 종료 문자열)
      데이터 블록
```

항목을 몇 바이트 단위로 맞추는지는 **묶음마다 다릅니다**(0x20 / 0x80 / 0x100). 원본에서 되읽어
그대로 써야 합니다(`wfu_pack.archive_align`). 마지막 항목 뒤에는 채움을 넣지 않습니다.

묶음 안에 묶음이 들어 있는 경우가 있습니다. 달력 도장이 `ui/ui_fb_tex.jarc` > `com_tex.jarc`
안에 있습니다. 안쪽 묶음도 jCMP로 포장돼 있습니다.

### jIMG (텍스처 컨테이너)

```
0x00  'jIMG'
0x04  u32  전체 크기
0x08  u16  너비, u16 높이
0x10  u32  GTX 시작 위치   (상위 바이트가 플래그라 하위 비트만 쓴다)
0x14  u32  GTX 길이
0x1C  u32  CRC32 — jIMG 전체(0x1C~0x24를 0으로 둔 상태)
0x20  u32  CRC32 — 확장자 없는 파일 이름
```

두 CRC를 다시 계산해 넣지 않으면 게임이 텍스처를 받아들이지 않습니다.

## 2. 대사 (BMG)

`JP/Message/message.carc` → Yaz0 해제 → U8 → `health_message.bmg`.

`MESGbmg1` 형식, UTF-16 빅엔디언, 섹션은 INF1(항목표) · DAT1(글자) · MID1(번호).
메시지 8,665개, 글자 약 177,000자, 고유 한자 6,720자.

제어 태그는 `0x001A` 로 시작하고 길이 바이트가 따라옵니다. 작업용 JSON·시트에서는 `{16진수}`로 적습니다.

| 태그 | 뜻 |
|---|---|
| `{ff0000XXXX}` … `{ff0000ffff}` | 글자 색 강조 |
| `{6400XXXXXX}` | 대기 — 음성에 맞춘 시간 |
| `{0000XX}` | 변수 (이름·숫자) |

글자 그대로의 중괄호는 `{{` `}}`로 적습니다.
U+E000~U+F8FF 사설 영역 문자는 버튼·아이콘 그림이라 그대로 두어야 합니다.

### 바이트 일치에 필요한 두 가지

- DAT1 본문은 32바이트 단위로 맞춥니다.
- **원본 파일은 헤더에 적힌 크기보다 8바이트 짧습니다**(MID1 꼬리가 잘려 있음). 이걸 따라야
  원본과 같아집니다.

### 번역하지 않는 것

기호·영문뿐인 문장, 글꼴 문자표 페이지(#6921~7035), #8495. 번역 대상은 7,821개입니다.

## 3. 글꼴 (JFNT)

```
0x00  'JFNT'
0x04  4B   00 8b 54 42 (모든 글꼴 공통)
0x08  u8   글자 최대 폭, u8 글자 높이, u8 칸 수(가로), u8 여백
0x0C  u16  범위 개수
0x0E  범위 6바이트 x N: u16 시작 문자, u16 끝 문자, u16 글리프 번호   (유니코드, 빅엔디언)
      u16 글리프 개수 + 글리프마다 폭 1바이트
      jIMG 글리프 아틀라스 1장
```

아틀라스는 `(최대폭+여백) x (높이+여백)` 칸을 가로로 늘어놓은 격자입니다.
형식은 **BC5**(디버그 글꼴만 BC4), tileMode 4, 한 줄이 2048블록, 행은 16의 배수로 채웁니다.
두 채널의 뜻은 **ch0 = 글자 속, ch1 = 외곽선**(속을 반지름 3으로 불린 것)입니다.

한글은 번역문에 실제로 쓰인 1,051자만 Noto Sans KR로 그려 넣습니다. 범위표에 한글 범위를 추가하고
아틀라스를 아래로 늘립니다.

낱개 `.jfnt` 파일과 `fonts/font_data.jarc` 안의 글꼴은 **같은 내용**입니다(묶음 안에서는 jCMP로
압축된 상태). 둘 다 바꿔야 합니다.

### 한자를 추가하면 안 되는 이유

번역되지 않은 문자표 페이지의 한자까지 글꼴에 넣었다가 글꼴 하나가 74MB로 부풀었습니다.
실기에서 메모리가 부족해질 수 있습니다. 지금은 번역된 문장에서만 글자를 모으고, 한자·가나는
추가하지 않도록 막아 두었습니다.

공백 문자도 추가하지 않습니다. 원본 글꼴에 공백 글리프가 없는데 넣으면 엔진의 공백 처리가 바뀝니다.

## 4. 텍스처 (GTX)

Wii U 표준 GTX(Gfx2 v7.1)입니다. 쓰이는 형식은 BC1(0x31) · BC2(0x32) · BC3(0x33) · BC4(0x34) ·
BC5(0x35) · RGBA8(0x1A)이고, 전부 tileMode 4(2D tiled thin1)입니다.

### 타일 배열 규칙

GPU가 픽셀을 늘어놓는 순서입니다. 공개 문서를 찾지 못해, 이미지가 매끄럽게 이어지는지를 점수로
매겨 비트 순서를 찾아냈습니다. 블록 좌표의 비트를 아래 순서로 늘어놓은 값이 저장 위치입니다.

```
pipe  = x3 ^ y3
bank0 = x3 ^ y5
bank1 = x4 ^ y4
```

| 한 칸 크기 | 비트 순서 |
|---|---|
| 4바이트 (RGBA8, 픽셀 단위) | x0, x1, y0, x2, y1, y2, pipe, bank0, bank1 |
| 8바이트 (BC1, BC4) | x0, y0, x1, x2, y1, pipe, bank0, bank1, y2 |
| 16바이트 (BC3, BC5) | y0, x0, x1, x2, pipe, bank0, bank1, y1, y2 |

형식마다 순서가 다릅니다. 하나를 알아냈다고 나머지에 그대로 쓸 수 없습니다.

### 블록 구성

- BC3 = 알파 8바이트(BC4 방식)가 **먼저**, 그다음 컬러 8바이트(BC1 방식).
- BC2 = 알파 4비트 8바이트 + 컬러 8바이트.

### 글자를 바꾸는 방식

1. `image_tool.py dump` — 원본 텍스처를 PNG로 뽑습니다.
2. `translation/image_text.json`에 영역과 한국어를 적습니다. 영역마다 원본 글자를 지울 방법
   (사각·타원 채우기, 투명 채우기)과 글자색·크기·정렬을 지정합니다.
3. `image_tool.py render` — 원본 위에 한글을 그립니다.
4. `image_tool.py build` — 다시 인코딩해 묶음을 꾸립니다.

도장 글자는 알파로 모양이 결정됩니다. 속을 `RGBA [255,255,255,0]`으로 채워 지웁니다.
도장에는 잉크 얼룩 텍스처(`cld_stampMura_00`의 ch1)를 글자 알파에 곱해 원본의 번진 느낌을 냅니다.

### 바꾼 텍스처 32장

| 파일 | 내용 |
|---|---|
| `JP/ui/wev_tex.jarc` | 튜토리얼 그림 5장 |
| `ui/mme_jpn_tex.jarc` | 기록·메뉴 패널 13장 |
| `ui/models_data.jarc` | 트레이닝 로고 (모델 안의 텍스처) |
| `ui/aot_tex.jarc` | 완료 도장 (済→완) — **본편에만 있는 파일** |
| `ui/ui_fb_tex.jarc` > `com_tex.jarc` | 달력 도장 12장 |

달력 도장은 `cld_te_check_NN`(98px) / `_L_NN`(224px) / `_filter_L_NN`(224px, 잉크 얼룩) 세 벌이
한 세트입니다. 번호는 01=済→완, 11=すみ→마침, 12=犬→개, 13=猫→고양이 입니다.

## 5. 배포용 패처

원본 게임 데이터를 담지 않고, 사용자가 가진 원본으로 한글판을 만드는 방식입니다.

- 묶음은 **안쪽에서 바뀐 항목만** 담습니다. 겉으로는 30MB가 바뀌지만 실제로 바뀐 안쪽 항목은
  0.85MB뿐입니다(`ui_fb_tex.jarc`는 1,774개 중 12개, `models_data.jarc`는 497개 중 1개).
- `font_data.jarc`는 낱개 글꼴 파일과 내용이 같으므로 낱개 쪽만 담고, 패처가 묶습니다.
- 패처는 원본 13개의 SHA-1을 먼저 확인하고, 만든 결과가 제작 환경에서 확인한 빌드와 SHA-1까지
  같은지 검사합니다.
- 재조립 코드(`tools/wfu_pack.py`)는 도구와 패처가 같은 파일을 씁니다. 파이썬 기본 기능만 쓰므로
  패처에 numpy·Pillow가 필요 없습니다.

패치 데이터 79MB, zip 22.5MB(내장 파이썬 포함), 적용 시간 2.3초입니다.

## 6. 밟은 함정

- **묶음 안의 묶음을 놓쳤습니다.** 달력 도장을 찾을 때 겉 묶음만 훑어 엉뚱한 `aot_tex.jarc`(다른
  화면의 도장)를 고쳤습니다. 실기에서 한자가 그대로라는 제보를 받고 나서 안쪽까지 재귀로 뒤져
  찾았습니다. 텍스처를 찾을 때는 묶음 안의 묶음까지 봐야 합니다.
- **안쪽 묶음 재압축을 빠뜨렸습니다.** 18MB 파일이 90MB가 됐습니다.
- **폴더 이름의 대괄호.** `Wii Fit U [Game] [...]` 같은 이름은 glob 패턴의 문자 클래스로 해석돼
  검색 결과가 0건이 됩니다. `os.walk`를 씁니다.
- **BC3 채널 순서.** 컬러가 먼저일 거라 짐작했지만 알파가 먼저입니다.
- **도장 번호.** 01/11/12/13 입니다(07은 없음). 세 벌 비교 시트를 만들어 확인했습니다.
- **덤프 목록에서 빠진 텍스처.** 도장 잉크 얼룩을 한 번 손으로 뽑아 쓴 탓에, 저장소만 받으면
  그림을 다시 만들 수 없는 상태가 됐습니다. 덤프 목록에 넣고 BC5 채널별 저장을 지원하게 고쳤습니다.
- **Cemu에서 실행되지 않습니다.** Cemu 호환성이 "Unplayable"입니다. 실기로만 확인할 수 있습니다.
